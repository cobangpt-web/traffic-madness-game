# 신호등 대환장 — 구현 계획

상태: MVP와 2단계 특수 차량·연쇄 정체 구현 및 QA 완료. 2026-08-12 기준 배포 가능한 정적 빌드 검증 완료.

## 1. 목표

한 손으로 두 신호 단계만 전환하면서 60초 동안 차량을 최대한 많이 통과시키는 탑다운 교통 관제 점수 게임을 만든다. PC와 모바일 브라우저에서 같은 규칙으로 플레이하며, 한 판이 짧고 즉시 다시 시작할 수 있어야 한다.

## 2. 확정된 MVP 범위

- 단일 4방향 교차로, 각 진입로 1차선
- 플레이 시간 60초
- 신호 단계는 `남북 통행`과 `동서 통행` 두 가지
- 단계 전환 시 황색 350ms와 전방향 적색 250ms를 반드시 거침
- 차량은 직진만 지원하고, 진입 방향과 색상은 시드 기반으로 결정
- 안전 통과 시 기본 100점, 연속 통과 시 콤보 보너스
- 충돌 시 500점 감점과 콤보 초기화, 3회 충돌 시 즉시 종료
- 15초마다 차량 생성 간격이 짧아지는 4단계 난이도
- 오늘 날짜로 만든 동일한 시드와 개인 최고 점수를 `localStorage`에 저장
- 키보드, 마우스, 터치 조작 및 일시정지
- 로그인, 광고, 결제, 전 세계 온라인 순위표는 MVP에서 제외

## 3. 게임 흐름

1. 시작 화면에서 플레이를 누르면 3초 카운트다운이 시작된다.
2. 네 진입로에서 차량이 시드에 따라 생성되고 정지선으로 이동한다.
3. 플레이어는 `남북` 또는 `동서` 버튼으로 다음 녹색 신호를 선택한다.
4. 녹색 차량은 교차로를 통과하고, 적색 차량은 정지선 뒤에서 대기한다.
5. 통과 차량이 이어질수록 콤보가 증가한다. 충돌하거나 대기열이 화면 끝을 넘으면 콤보가 끊긴다.
6. 60초가 끝나거나 3회 충돌하면 점수, 최고 기록, 다시 하기 버튼을 표시한다.

## 4. 화면 구성

- 상단 HUD: 게임명, 점수, 남은 시간, 콤보, 최고 기록, 일시정지
- 중앙: 화면 대부분을 차지하는 단일 교차로와 네 방향 차량 대기열
- 교차로 주변: 색상 외에도 켜진 램프의 위치와 밝기로 상태를 구분하는 신호 표시
- 하단: 모바일에서도 누르기 쉬운 `남북`, `동서` 대형 버튼
- 화면 비율: 16:9 기준, 다른 비율에서는 레터박스 또는 안전 영역 확장

시각 기준은 [gameplay-screen-v1.png](gameplay-screen-v1.png)이다. 이 PNG는 화면 구성을 위한 목업이며, 실제 게임 월드는 Kenney 원본 스프라이트와 CSS 도형으로 다시 구성한다.

## 5. 에셋 정책

- 월드 오브젝트는 Kenney `Racing Pack`의 자동차, 도로, 잔디, 나무, 방호벽, 콘만 사용
- HUD, 신호등, 버튼은 HTML/CSS 기본 도형으로 제작
- 효과음은 현재 보유한 Kenney CC0 사운드만 사용
- 실제 프로젝트에는 사용하는 파일만 복사하고 원본 `License.txt`와 `assets.json` 출처 목록을 함께 보관
- 다른 프로젝트 폴더를 런타임에 직접 참조하지 않음
- AI 목업 이미지를 도로, 자동차, 나무 등의 실제 게임 텍스처로 사용하지 않음

## 6. 기술 설계

### 선택 기술

- 빌드: Vite + TypeScript
- 월드 렌더링: HTML5 Canvas 2D
- HUD와 입력: 시맨틱 HTML + CSS
- 상태 저장: `localStorage`
- 테스트: Vitest + Playwright
- 배포: 정적 호스팅

### 선택 이유

| 기준 | Canvas 2D + DOM | Phaser | React + Canvas |
|---|---:|---:|---:|
| 단일 화면 구현 단순성 | 5 | 3 | 3 |
| 자동차 수 증가 시 성능 | 5 | 5 | 4 |
| HUD 접근성 | 5 | 3 | 5 |
| 기존 코드 의존성 최소화 | 5 | 3 | 3 |
| 게임 기능 확장성 | 3 | 5 | 4 |

MVP는 장면 하나와 단순한 충돌 규칙만 필요하므로 Canvas 2D와 DOM 조합을 선택한다. Phaser의 장면·물리 기능은 이번 범위에는 과하며, React 상태와 매 프레임 게임 상태를 섞을 이유도 적다.

### 내부 계약

```ts
type SignalPhase = "NORTH_SOUTH" | "EAST_WEST";

interface TrafficGame {
  start(seed: number): void;
  selectPhase(phase: SignalPhase): void;
  pause(): void;
  resume(): void;
  step(deltaMs: number): void;
  snapshot(): Readonly<GameSnapshot>;
}

interface ScoreRepository {
  loadBest(dailySeed: string): number;
  saveBest(dailySeed: string, score: number): void;
}
```

외부 네트워크 API는 MVP에 없다. 나중에 온라인 순위표를 추가할 경우 `ScoreRepository`의 원격 구현만 교체할 수 있게 경계를 둔다.

### 핵심 데이터

- `GameSnapshot`: 상태, 남은 시간, 점수, 콤보, 충돌 횟수, 신호 상태, 차량 목록
- `Vehicle`: ID, 진입 방향, 위치, 속도, 색상, 상태
- `SignalController`: 현재 단계, 전환 단계, 남은 전환 시간
- `RunResult`: 날짜 시드, 최종 점수, 최대 콤보, 통과 수, 충돌 수

## 7. 작업 순서

### Task 1 — 프로젝트와 에셋 기반

- Vite + TypeScript 프로젝트를 만들고 Canvas와 HUD 루트를 분리한다.
- Racing Pack에서 실제 사용하는 에셋만 프로젝트 안으로 복사한다.
- 라이선스와 출처 매니페스트를 포함하고 누락 파일 검사를 추가한다.

완료 조건: 개발 서버와 프로덕션 빌드가 오류 없이 실행되고, 모든 매니페스트 경로가 테스트에서 확인된다.

### Task 2 — 결정적 교통 시뮬레이션

- 고정 시간 간격, 시드 RNG, 차량 생성·정지·통과·충돌을 구현한다.
- 황색과 전방향 적색을 포함한 신호 상태 머신을 구현한다.
- 점수, 콤보, 난이도 상승, 종료 규칙을 순수 로직으로 만든다.

완료 조건: 같은 시드와 같은 입력은 항상 같은 결과를 만들고 경계 조건 단위 테스트가 통과한다.

### Task 3 — 렌더러와 실제 게임 화면

- Kenney 원본 스프라이트로 교차로, 차량, 환경물을 그린다.
- 목업과 동일한 정보 계층으로 HUD와 터치 버튼을 구성한다.
- 화면 크기와 DPR 변화에 대응하고 16:9 안전 영역을 유지한다.

완료 조건: 1280×720과 390×844에서 정보가 잘리지 않고, 차량 40대 상태에서 부드럽게 동작한다.

### Task 4 — 조작, 저장, 접근성

- 터치·마우스·키보드 입력, 일시정지, 다시 시작을 연결한다.
- 날짜 시드와 개인 최고 기록을 안전하게 저장한다.
- 색상만으로 신호를 구분하지 않도록 라벨과 램프 위치를 병행한다.

완료 조건: 손상된 저장 데이터에서도 게임이 시작되고 키보드만으로 전체 흐름을 완료할 수 있다.

### Task 5 — 피드백과 첫 플레이 안내

- 보유 CC0 효과음, 충돌 흔들림, 콤보 피드백, 게임 종료 화면을 추가한다.
- 첫 판에만 2단계 조작 안내를 표시한다.
- 음소거와 `prefers-reduced-motion`을 지원한다.

완료 조건: 에셋 로딩 또는 오디오 재생이 실패해도 게임 진행이 중단되지 않는다.

### Task 6 — 통합 검증과 배포 준비

- 전체 60초 플레이, 재시작, 저장 복구, 모바일 터치를 E2E로 검증한다.
- 빌드 결과, 콘솔 오류, 에셋 404, 프레임 시간을 확인한다.
- README와 정적 배포 설정을 작성한다.

완료 조건: 단위·E2E·빌드가 통과하고, 대상 화면에서 콘솔 오류와 에셋 404가 없으며, 중급 PC 기준 60fps를 유지한다.

## 8. 주요 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 신호를 지켜도 충돌 원인이 불명확함 | 불공정하게 느껴짐 | 충돌 예고 영역과 전환 타이머를 시각화하고 결정적 리플레이 테스트 추가 |
| 차량이 많을 때 겹침 또는 떨림 | 완성도 저하 | 차선별 선두 차량만 정지선을 판정하고 고정 틱 사용 |
| 작은 모바일 화면에서 HUD가 월드를 가림 | 조작 어려움 | HUD 높이 상한과 16:9 안전 영역, 세로 화면 회전 안내 제공 |
| 외부 에셋 출처가 누락됨 | 배포 리스크 | 라이선스 파일과 매니페스트를 빌드 전 자동 검사 |
| 단일 교차로가 빨리 반복적으로 느껴짐 | 재방문율 저하 | MVP 이후 일일 변형 규칙과 특수 차량을 추가하되 첫 버전에는 넣지 않음 |

## 9. MVP 이후 후보

### 구현 완료된 2단계 기능

- 전용 구급차 스프라이트, 진입 사이렌, 우선 통과 300점 보너스
- 초반 첫 구급차 보장, 이후 최소 18초 간격과 한 판 최대 3대 제한
- 같은 색 차량 연속 통과 시에만 이어지는 색상 콤보
- 사고를 목격한 인접 접근로의 선두차 급정거와 5초 연쇄 정체
- 급정거 차량 경고 아이콘, 접근로 경고 영역, HUD 정체 타이머
- 2단계 `러시아워 웨이브`: 10초 단위로 교통량이 폭증하는 6개 웨이브
- 웨이브가 올라갈수록 차량 생성 간격이 짧아지고, 웨이브 클리어마다 300점 보너스

1. 익명 온라인 일일 순위표
2. 좌회전·우회전 차량과 버스
3. 비·야간 등 시야 규칙
4. 두 교차로를 동시에 관리하는 고난도 모드
5. 결과 공유 카드와 친구 기록 고스트
